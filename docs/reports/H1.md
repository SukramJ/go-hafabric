## Model

- `hamapping.Map(dev *model.Device, entities []model.Entity) (*Plan, []Verdict)`:
  per entity a `Verdict` (`eligibility.Verdict` with the entity's `Key` and
  the deciding `Row`; Mappable/Partial carry `DeviceType` and `Clusters`,
  Partial/Unmappable a reason) and, for a mapped entity, an `Endpoint{Key,
  Row, Type *device.Type, Options device.Options, Declarations
  []device.Declaration, Features, Bindings, Riders}`. One endpoint per
  entity; a row with `ride: primary` (the battery sensor) puts its value on
  the device's first non-riding mapped endpoint, else gets its own.
- `Plan.Build(ctx) ([]*device.Device, error)`: `device.New` per endpoint, the
  type's required parts (`AddPart`), then the change hooks.
- `Plan.Apply(ctx, key, model.State) []Patch`: `SetReachable` from
  `State.Available` (not for a rider), then one typed `<cluster>def.Patch`
  `Set` per mapped cluster; each `Patch` carries the typed value and the
  `Set`'s error.
- `Plan.OnChange(func(model.Command))`: a controller's command (typed
  `Declare.Handle<Command>`), write (`Declare.OnWrite`) or a change the kit's
  server made running a command (`Device.OnChanged`, origin
  `OriginCommand`) becomes `model.Command{Entity, Role: command, Slot}` (the
  entity's command binding) or `{Entity, Method}` (a named method), with the
  payload in the entity's command form (JSON for the light, the catalog's
  `payload_*` defaults otherwise). Delivered inline; the function must not
  block.
- The table: `rows/<platform>.yaml` → `internal/rowfile` (YAML, known fields
  only) → `internal/gen` (every name checked against go-fabric's generated
  `device` and `<cluster>def` packages by reflection; emits typed closures:
  `declare`, `apply` with typed switches and `conv[T]`, `watch`) →
  `rows_gen.go`, plus the row table of `docs/rows.md`.

## Differences (from the brief)

- `hamapping.Plan(dev)` is `hamapping.Map(dev, entities)`: Go cannot name a
  function and a type `Plan`, and go-hamqtt's `model.Device` holds no
  entities (they come from its `EntitySource`), so the entities are an
  argument. `Verdict` wraps `eligibility.Verdict` with the entity key and row.
- `Plan.Apply` takes a `context.Context` (for `SetReachable`) and applies the
  patches itself, returning them with their errors.
- `Endpoint.Type` is `*device.Type` (go-fabric's types are shared pointers);
  `Endpoint.Options` is `device.Options` and the declarations are
  `Endpoint.Declarations`.
- The battery rider is go-fabric's battery measurement source
  (`device.Measurement`, the cookbook's v0.10.8 route), not
  `powersourcedef.Declare`: the typed declaration on a bridged device fails
  go-fabric v0.11.0's own validator (Questions Q1). The row is Partial with
  the reason, per hard rule 3.
- `SmokeCoAlarm` needs a PowerSource device part (smoke-co-alarm-device
  element :28, `min 1`); rows gained `parts` for it.
- go-ha-catalog `d9582e02` is no tag (latest tag `v0.3.1` carries snapshot
  2026.10.0): the module pins the pseudo-version. go-hamqtt `d1bb9ac9` is
  one CI-only commit after `v0.38.0`: the module pins `v0.38.0`.
- `gopkg.in/yaml.v3` is not in go-hamqtt's (nor go-fabric's) graph, as the
  brief assumed: it is a new module of the graph, used by `internal/rowfile`
  only.
- "Commands through `Server.OnWrite`/`Handle<Command>`": a third mechanism,
  `change` (the cluster's change hook with origin `OriginCommand`), carries
  the commands whose semantics the kit's server computes (OnOff Toggle,
  MoveToLevel, the colour commands, SetpointRaiseLower), so the controller
  sees the kit's state at once; `handle` is used where the device, not the
  kit, moves (cover, lock).

## Decisions

- **State convention.** A composite platform's state is a map with HA's
  attribute keys (the MQTT JSON light's `state`, `brightness`, `color`,
  `color_temp`, `color_mode`; the climate's `current_temperature`,
  `temperature`, `target_temp_low/high`; the cover's `current_position`; the
  fan's `percentage`, `preset_mode`, `oscillating`, `direction`), else
  `State.Extra`. `state` is the primary value. A binary value reads on/off
  from a bool, ON/OFF or true/false.
- **Capabilities** come from `Description.Extra` under the catalog's key
  names, with the catalog's default where the entity states none (climate
  `modes` defaults to the catalog's list, so a climate without `modes` is a
  Partial heating-and-cooling thermostat); `present` asks the entity only
  (the catalog has defaults for `fan_modes` and `swing_modes`).
  `supported_features` is the catalog's bit mask or flag names.
- **Commands.** The command binding's payload is the catalog's default
  `payload_*` (or the entity's own key); a named method is the platform's
  `<method>_command_topic` prefix (`set_position`, `tilt`, `mode`,
  `temperature`, `temperature_low/high`, `percentage`, `preset_mode`,
  `oscillation`, `direction`). A light's colour command is handed out only
  in the colour mode the controller set (`if: ColorMode`), and the
  mode-switch conversion change is skipped (`unless: [ColorMode]`), so a
  command is one `model.Command` (`noMore` in the tests).
- **Conversions** are linear per unit from the row (the physics of HA's
  units; for °F, K, every pressure, power, voltage, current and energy unit
  of the catalog); illuminance follows the element's formula
  (`10000·log10(lx)+1`, 0 for below 1 lx); brightness follows go-fabric's
  `LevelFromUnit` (`brightness/brightness_scale·254`, clamped 1..254).
- **Electrical sensors** are declared AC with `NodeTopology` and the widest
  accuracy range (±2^62, resolution 1), as the cookbook's shape: HA states
  neither AC/DC nor accuracy.
- **Occupancy.** motion → PassiveInfrared; occupancy/presence → Other with
  the deprecated mandatory OccupancySensorType at its first value and an
  empty bitmap (matter.js leaves both unset for Other).
- **Smoke/CO** on → AlarmState Critical; the required PowerSource part is a
  battery of unknown charge.
- **Measurement clusters** declare MeasuredValue, MinMeasuredValue and
  MaxMeasuredValue null until a state arrives (Questions Q2).
- **Cover** device classes map to Type/EndProductType where the enum has one
  (shutter, blind/shade, curtain, awning); garage, gate, door, damper and
  window are Unknown with a caveat.
- **Climate**: heat → Heating, cool → Cooling, heat_cool → both and AutoMode
  (SystemMode Auto ↔ heat_cool); HA's `auto` (the device's schedule) is not
  mapped (caveat); dry and fan_only map to SystemMode Dry/FanOnly.

## Left out

- Ecosystem-aware type choice (`eligibility.Compat`), composition beyond the
  battery rider and SmokeCoAlarm's part, ModeSelect for `select`,
  GenericSwitch for `event`, AirQualitySensor for the concentration classes,
  DoorLock Unbolting, thermostat presets, fan/swing modes, the cover's
  OperationalStatus, the light's effect and transition, the light's
  basic/template MQTT schemas (the rows read the JSON schema's state and
  command shape).
- The v0.1.0 tag (the owner's).

## Questions

- **Q1 (kit gap).** `powersourcedef.Declare` on a bridged device (any type
  that does not list PowerSource) fails go-fabric v0.11.0's device-type
  validator: `missing BridgedNode PowerSourceConfiguration: Mandatory server
  cluster PowerSourceConfiguration is missing` — BridgedNode lists it under
  `BridgedPowerSourceInfo, D` (bridged-node.element.ts:22), which
  `device.withBridgedPowerSource` leaves out, and `powersourceconfigurationdef.Declare`
  is refused (`TemperatureSensor has no server cluster requirement for
  cluster 0x002E`). Needed: the kit mounts PowerSourceConfiguration (or the
  validator reads `D` as not mandatory) when `withBridgedPowerSource`
  appends PowerSource. The cookbook's typed ElectricalSensor + PowerSource
  form is the same declaration (not probed here). Workaround: the rider uses
  `device.Measurement` with `contract.MeasurementBattery`; the row is Partial.
- **Q2 (kit gap).** A kit measurement server without a value for a mandatory
  nullable attribute answers a wildcard read with UnsupportedAttribute
  (TemperatureMeasurement 0x0000/0x0001, OccupancySensing
  OccupancySensorType 0x0001, SmokeCoAlarm BatteryAlert 0x0003, FanControl
  FanMode 0x0000) instead of its null or default; the validator passes it.
  Needed: the kit's defaults (null for nullable mandatory attributes, the
  enum's default) in `device.New` (`defaults.go`). Workaround: the rows
  declare them (`start_null`, constants).
- **Q3 (go-hamqtt gap).** `model.Description` has no typed capability set:
  `supported_color_modes`, `supported_features`, `modes`, `preset_modes`
  travel in `Extra` under the catalog's names (the discovery renderer copies
  `Extra` verbatim). Needed: a typed `Description.Features` (catalog flag
  names) or a documented `Extra` contract.
- **Q4 (go-hamqtt gap).** `model.State` carries one `Value`: the composite
  platforms' attributes (brightness, colour, current_temperature, position)
  have no typed slot; the rows read a map `Value` or `State.Extra`. Needed:
  the convention stated in go-hamqtt (or `State.Attributes`).
- **Q5 (go-hamqtt gap).** `model.Command` addresses a named method by string
  only; the platforms' secondary command topics (`set_position_topic`,
  `mode_command_topic`, `percentage_command_topic`) have no role. The rows use
  the topic key's prefix as `Method`; a daemon's `Commander` must route it.
- **Q6.** The brief names `OnOffSensor` for a binary_sensor without a class;
  its OnOff is a client cluster, so a controller sees no state. Keep it
  Partial, or map such a sensor to ContactSensor?

## by_design candidates

The helper reference home-assistant-matter-bridge is not local (the read map
§6 confirms it); compared against matter.js at `862ad75f` (elements,
resources, `OccupancySensingServer.ts`) and go-fabric's kit only.

- The battery as a measurement rider, not a declared PowerSource (Q1).
- Commands caught on the kit's change (`change`) for OnOff, LevelControl,
  ColorControl and the thermostat's SetpointRaiseLower, so the kit's server
  runs the command (Toggle, ExecuteIfOff, the colour-mode conversion) and
  the entity gets the result; the cover and the lock replace the kit's
  handler instead, their state following the device.
- Electrical sensors declared AC with the widest accuracy range.
- occupancy/presence as OccupancySensing Other with the deprecated sensor
  type at its first value.
- HA climate `auto` left unmapped; heat_cool ↔ SystemMode Auto.
